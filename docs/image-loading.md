# 手机图片加载检查

2026-10-06：用户报告微信里的图片持续空白，复制到手机浏览器后也加载很慢。维护端逐一请求首页图片，均返回 HTTP 200 和正确的图片类型；这不能证明用户手机到托管站点的连接正常，也不能把此次代码调整写成已经完成手机微信实测。

已修复的代码问题：

- 首页第一张画在 HTML 中就有真实地址和可见样式，外部脚本未到达时也能显示。画册与小卡片以图片加载事件判断可用性，增加 12 秒超时，不再无限等待额外的 `decode()` 或无关字体下载。慢请求不再依次触发十一张图片的下载；当前画面保留，最初请求晚到时仍可恢复。
- 画册预览只选择 480/800px 网页副本；放大查看继续使用原图。不提前下载隐藏的下一幅画，以减少与当前页面图片的竞争。
- 客席作者头像与封面生成响应式副本，列表、相册目录和文章尾部按实际显示尺寸选择。CHAYu 的 240px 头像从原文件的 336244 字节降为 16854 字节。相册目录使用 52px 圆头像。
- `ResponsiveArt` 向根图片传递父组件的样式作用域属性，避免缩略图被原始宽高撑开。
- Markdown 正文图片使用 Astro 原生响应式输出，保留原文、图片比例和稳定文章地址。
- 相册查看器的数据改为 JSON，交互脚本交给 Astro 编译，不再将 TypeScript 类型声明直接输出给浏览器。站点检查加入内联脚本语法检查。
- 空相册保留真实的空状态说明，删除带星号的大占位框；不往空相册填入作者头像或其他照片作为作品。

`npm run check:image-loading` 检查已有图片、加载完成、错误、超时和缓存失败的行为，并纳入发布工作流。发布前同时运行构建、站点检查、文库检查和内容状态检查。

托管仍沿用现有 GitHub Pages，域名和 DNS 没有改动。若更新后同一手机仍明显慢，需要进一步验证访问链路及托管线路，不能仅凭更换格式或反复刷新断言问题已解决。
